# Explainable AI (XAI)

SchemeSetu explains **why** each scheme received its status using only the evidence the deterministic
engine produced. The LLM is optional wording on top, and its text is checked before it is shown.

## Evidence model (`backend/app/eligibility/models.py`)
`RuleResult` per rule: `field`, `operator`, `user_value`, `required_value`, `status` (PASS / FAIL / UNKNOWN /
NOT_APPLICABLE), `source_text` (quotation from the official source), `source_url` (the scheme's official
URL from the corpus, never invented), `logical_group`, `required`, `rule_id`.
`EligibilityResult` per scheme: `status`, counts, `missing_information`, `conflicts`, `source_references`,
`corpus_version`, `engine_version`.

## What the user sees
| Status | Explanation content |
|---|---|
| ELIGIBLE | "Your profile matches the available eligibility criteria." + matched criteria (✓ Field: value). OR-alternatives or optional rules that did not match are listed as "Other options (not needed…)" |
| NOT_ELIGIBLE | Failed criteria with profile value, required value and source text (exclusion reasons) |
| NEEDS_MORE_INFORMATION | The missing fields (○ Field, required value) — never treated as failed |
| UNVERIFIABLE | "The available structured criteria are insufficient to make a reliable assessment." No criteria are claimed |

Scheme cards (`frontend/src/components/SchemeList.tsx`) show the same evidence with a status badge and
text label (not colour alone), plus documents, application steps and the official source link.

## Uncertainty handling
- Unknown profile values stay **UNKNOWN** (three-valued Kleene logic); they never become FAIL.
- Contradictory rules (numeric bounds or disjoint required values) → UNVERIFIABLE + human review.
- No probability or "confidence score" is produced. `profile_match_score` is a ranking signal (matched ÷
  evaluated rules), not a likelihood of approval.

## Unsupported-claim prevention
1. Explanations are generated by deterministic templates (`xai/templates.py`) from evidence only.
2. `validate_explanation` (`xai/explainer.py`) rejects text that claims eligibility against the engine status,
   contains numbers or URLs not in the evidence, or states criteria for fields that were never evaluated.
3. `validate_llm_response` (`xai/response_validator.py`) checks the LLM's reply against the structured scheme
   cards: eligibility claims per scheme, global "eligible for all" claims, URLs, money amounts and scheme names.
   On any violation the deterministic reply is used instead.
4. Retrieved web text is marked as untrusted data in the prompt; the engine never reads it.

## Measured evidence (Phase 7, offline)
32 XAI scenarios + 128 fabrication probes: status, claim, number and URL grounding 100%; fabrication
probes rejected 128/128 (26/128 before fixes); official source cited when available 100% (0% before).
See `docs/phase7-final-scorecard.md`.

2026-09-26 (per scheme in the DB).

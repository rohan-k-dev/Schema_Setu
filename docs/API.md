# SchemeSetu API

- Live, generated documentation: `GET /docs` (Swagger UI) and `GET /redoc` on the running backend.
- Machine-readable schema at release time: [`docs/api/openapi.json`](api/openapi.json). Regenerate with
  `cd backend && python -c "import json;from app.main import app;json.dump(app.openapi(),open('../docs/api/openapi.json','w'),indent=2)"`.
- Base URL locally: `http://localhost:8000`. All bodies are JSON unless noted. There is **no rate limiting**
  (no 429 responses); deploy behind a proxy that rate-limits if needed.

## Conventions
| Code | When |
|---|---|
| 200 | Success. Conversation endpoints also return 200 for handled failures, with `status:"error"` and an `error {code, message, request_id}` object |
| 400 | Invalid review action or status transition |
| 401 | Not signed in (no session cookie / expired / deactivated account) |
| 403 | Role lacks the permission (`FORBIDDEN`), missing CSRF token, or a wrong / disabled `X-Review-Key` |
| 404 | Unknown scheme ID, review case or route |
| 422 | Request validation (bad JSON, missing file, message > 2000 chars, blank message, out-of-range query params) |
| 500 | Unhandled server error: `{"status":"error","error":{"code","message"}}`. No stack traces are returned |

Error codes in `error.code`: `VALIDATION_ERROR`, `VOICE_TRANSCRIPTION_FAILED`, `CONFIGURATION_ERROR`,
`EXTERNAL_SERVICE_ERROR`, `LANGUAGE_SERVICE_UNAVAILABLE`, `TTS_EMPTY`, `INTERNAL_ERROR`. Messages never contain
secrets, environment-variable names or driver errors.

## Health
| Method | Path | Response |
|---|---|---|
| GET | `/` | `{"message":"SchemeSetu API is running.","version":"1.0.0",...}` |
| GET | `/health/live` | `{"status":"alive"}`. Liveness only |
| GET | `/health` | `{"status":"healthy","db_connected":true,"graph_available":true,"environment":"production","version":"1.0.0"}`. `degraded` if the DB or graph is down |
| GET | `/health/ready` | `{"status":"ready"|"not_ready","db_ready","graph_ready","groq_configured","tavily_configured","sarvam_configured"}`. Ready = DB up **and** Groq configured |

## Conversation
### POST /chat
Request: `{"message": "I am a farmer from Karnataka with 2 acres growing ragi", "thread_id": "<uuid>", "language": "en"}`
(`message` 1–2000 chars, not blank; `thread_id` ≤128 chars, one per conversation, generated by the client;
`language` one of the codes from `/languages`).

Response (`ChatResponse`, abbreviated from a real run):

### POST /voice (multipart/form-data)
Fields: `file` (audio; WAV, WebM, Ogg, MP3, MP4, FLAC; ≤10 MB; content must match the declared type),
`thread_id`, `language`. Response: `ChatResponse` plus `user_transcript`. Validation failures:
`status:"error"`, `error.code:"VALIDATION_ERROR"`.

### POST /tts
Request `{"text": "...", "language_code": "kn"}` (≤5000 chars; `kn` or `kn-IN`). Response
`{"audio_base64": "<wav>"}` or `{"audio_base64": null, "error": {...}}`.

### GET /languages
`{"languages": [{"code": "kn", "name": "ಕನ್ನಡ", "english_name": "Kannada", "has_voice": true, "has_tts": true}, ...]}`
(11 entries).

## Canonical scheme data
| Method | Path | Notes |
|---|---|---|
| GET | `/schemes?state=&crop=&query=&limit=` | Search canonical schemes (`limit` ≥ 1) |
| GET | `/schemes/{scheme_id}` | Full record with rules, documents, steps, sources. 404 if unknown |

## Human review (signed-in REVIEWER; dev-only `X-Review-Key`; see [RBAC.md](RBAC.md))
See `docs/HUMAN_REVIEW.md`. `GET /review-cases[?status=]`, `GET /review-cases/{id}`,
`POST /review-cases/{id}/resolve` `{"action":"REQUEST_INFORMATION|APPROVE|REJECT|MARK_UNVERIFIABLE","note"}`,
`POST /review-cases/{id}/dismiss` `{"note"}`, `GET /review-cases/stats/summary`. The reviewer is the
authenticated principal (`reviewer_id` in the body → 422).
Example: `curl -H "X-Review-Key: $REVIEW_API_KEY" http://localhost:8000/review-cases?status=PENDING`.

## CORS & authentication
CORS origins come from `CORS_ORIGINS`. End users are anonymous (session = client-generated `thread_id`);
only the review API is authenticated (shared key).
